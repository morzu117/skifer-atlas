## 3. Point de reprise : #228, comparaison Databricks réelle depuis l'écran (#31)

**Fait et poussé, sans avoir encore tourné contre le vrai warehouse :**

- `app/e2e/comparaison-databricks-reelle.spec.ts` est sautée sans les variables, donc inerte en
  CI. Elle repointe `dbx-fr` de la démo Nordis sur le vrai warehouse, dans l'espace isolé. Elle
  saisit le jeton par le vrai geste : OAuth refusé, « Utiliser un token personnel », « Ranger
  dans le coffre », « Tester ». Elle lance nordis-fr seule depuis l'écran, puis compare à l'oracle
  DuckDB.
- **Oracle** : 8 mois, de févr. à sept. 2026, de 5 163 000 à 5 313 500 (pas de 21 500), 100 % de
  validation, écart max 0,0 %, cellule `pass` au seuil de 99 %. Le test vérifie aussi le détail,
  l'historique et l'accessibilité (axe).
- `core/tests/databricks_recette.py load|drop <état.json>` charge `gold.finance.fact_facturation`
  et `gold.finance.dim_date`, les noms exacts lus par les documents de la démo. Il note chaque
  objet avant de le créer, ne supprime que ce que le passage a créé, et refuse de remplacer une
  table `gold` qui n'est pas une table de recette.
- Contrôles locaux verts : ruff, E30x, tsc, Vitest (732), pytest (2188 passés, couverture 95 %).

**Décision prise, option 1** : le passage crée le catalogue `gold` dans la Free Edition et le
supprime à la fin, seulement s'il l'a créé.

**À faire, dans l'ordre :**

1. `git switch test/31-comparaison-databricks-reelle && git pull`.
2. Passage réel, depuis `app/`, ports de la suite libres, **sans `--trace on`** (la trace
   enregistrerait le jeton) :

   ```sh
   ATLAS_DATABRICKS_HOST=https://<ton-workspace>.cloud.databricks.com \
   ATLAS_DATABRICKS_WAREHOUSE=<id du warehouse> \
   ATLAS_DATABRICKS_TOKEN="$(databricks auth token --profile atlas-free | jq -r .access_token)" \
   npx playwright test --project=chromium --reporter=line --workers=1 e2e/comparaison-databricks-reelle.spec.ts
   ```

   Le port 8020 doit être libre : pas de `databricks auth login` en cours.
3. Vérifier ensuite qu'il ne reste rien : `databricks catalogs list --profile atlas-free`, où
   `gold` ne doit plus apparaître. Si le passage a été tué avant le nettoyage, relancer `drop` :
   `cd core && uv run python tests/databricks_recette.py drop <état.json>`, avec les mêmes
   variables. Le chemin de l'état est affiché au début du passage.
4. **Points à surveiller au premier passage**, d'après l'agent qui a écrit la spec :

## 6. Consignes de travail (mémoire locale recopiée)

- **Langue : français.** Questions ouvertes en texte, en liste numérotée, avec une
  recommandation, pas de formulaire.
- **Aucune notion de « PS »** : ni le profil Databricks par défaut de l'autre Mac, ni les outils
  ou ressources PS. Uniquement nos propres outils et le workspace Free Edition perso.
- **Codex code, Claude orchestre** : brief, relecture du diff, suites, PR, fusions. Les tests
  Playwright sont écrits par un agent Claude. Commande :
  `codex exec -m gpt-6.1-terra -c model_reasoning_effort="high" -s workspace-write --add-dir ~/.cache/uv --add-dir /private/tmp -C <worktree> -o <sortie.md> - < <brief.md>`.
  Le bac à sable Codex n'a ni réseau ni sockets : les tests à port local, mutmut et les appels
  réels se lancent hors bac à sable. Briefs et sorties dans `~/Projects/atlas-briefs/`, à
  recréer sur la tour si besoin.
- **Pas de chantier suivant sans tests verts.** Un correctif a un test qui échoue sans lui,
  vérifié en retirant le correctif. Les docs font foi.
- **Fusion uniquement sur une CI verte et un main à jour.** Rebaser et attendre la CI après
  chaque fusion, jamais deux fusions d'affilée sur d'anciennes CI. Ne jamais baisser un seuil de
  couverture.
- **Python** : avant commit, dans `core/`, lancer `uv run ruff check .` puis
  `uv run ruff check --preview --select E301,E302,E303,E305,E306 .`. Jamais
  `monkeypatch.undo()`. Suite complète :
  `ATLAS_DATA_DIR=$(mktemp -d) ATLAS_VAULT=memory uv run pytest -q -p no:cacheprovider --ignore=mutants --cov=skifer_atlas`
  (~12 min, ~2190 tests). En zsh, ne pas passer une liste de fichiers par une variable non
  découpée.
- **Playwright** : ports fixes, une suite à la fois. Depuis `app/`, lancer
  `npx playwright test --project=chromium --reporter=line --workers=1 <fichiers>`, puis
  `--project=webkit`. Tests des gestes réels, docs comme oracle. Le clavier sous WebKit n'est pas
  prioritaire (`test.fixme`).
- **Pas de recette manuelle** quand on peut l'automatiser : Playwright fonctionnel, parcours de
  bout en bout ou sonde réelle hors CI.
- **Sécurité** : serveur Python sur 127.0.0.1 avec token. Les jetons de plateforme restent au
  coffre local ou dans l'environnement, jamais dans le dépôt.
- **Git** : pas de `git stash` nu. Les décisions vont dans `docs/decisions/`, sans toucher
  `docs/decisions/README.md` (pas d'index).
